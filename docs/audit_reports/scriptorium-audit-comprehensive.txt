Scriptorium ("Ars Arcanum") — Comprehensive Multi-Role Audit ReportRepository audited: https://github.com/aryansinghnagar/Scriptorium (cloned HEAD, v1.6.0 source / v1.6.1 CHANGELOG)Audit performed: 2026-09-21Auditor composition: 7 independent deep-dive audits (Senior Software Developer, Systems Engineer, Linux Developer, Code Architecture Analyst, Code Quality Analyst, Targeted End User, Security Engineer)Total findings: 213 individual findings across all rolesAggregated (deduplicated) findings: 47 cross-cutting findingsOverall project grade: B (GPA 2.93 / 4.00) — production-adoptable for the documented single-author Linux-Mint/Debian niche, with concrete improvement roadmap to reach A---1. Executive SummaryArs Arcanum (repo: Scriptorium) is a sovereign, local-first, Linux-only authoring and worldbuilding ecosystem that orchestrates seven external tools (Git, Pandoc, Typst, Obsidian, novelWriter, Calibre, LibreOffice) over a four-tier Markdown + YAML + OpenXML file hierarchy. It is the work of a disciplined solo developer who has clearly studied Debian Policy, Flatpak documentation, POSIX crash-safety, STRIDE threat modeling, and software-architecture literature. At ~44,600 lines of code (101 Python files + 22 Bash scripts) with 281 passing tests, a 7-stage verification harness, golden-value physics tests against published scientific benchmarks, and SHA-pinned CI actions, it is materially more carefully engineered than the typical open-source writing tool.This comprehensive report merges seven independent deep-dive audits (totalling ~72,000 words of per-role analysis) into a single unified document. After deduplication, the cross-role findings collapse to 47 distinct issues, of which 4 are Critical, 12 are High, 18 are Medium, 9 are Low, and 4 are Info. The single most striking pattern is convergent validation: multiple independent auditors — using different methodologies, different lenses, and different mental models — independently surfaced the same handful of structural issues. The 3,873-line `ui_gtk3.py` god-class was flagged by three roles (Software Dev, Code Architecture, Code Quality). The dual Bash/Python dispatcher drift was flagged by three roles (Software Dev, Code Architecture, Code Quality). The `atomic_write` fallback boilerplate pasted across 44 module heads was flagged by four roles. This convergent signal is the strongest possible evidence that these are real problems, not artifacts of any single auditor's bias.Top 3 cross-cutting strengths:Operational discipline uncommon for a beta. Every Bash script uses `set -euo pipefail`, transactional `mktemp -d` staging with `trap cleanup EXIT INT TERM`, NUL-delimited filename iteration, and explicit exit-code contracts (0/1/2/3). Every external binary download is SHA-256 fail-closed verified. The atomic-write primitive (`scripts/lib/fs_utils.py:12-65`) is textbook POSIX crash-safety: `mkstemp` → `flush` → `fsync` → `os.replace` → parent-directory `fsync` → cleanup on `BaseException`. The 7-stage `verify.sh` harness sandboxes `$HOME`, unsets `DISPLAY`/`WAYLAND_DISPLAY`, and runs an end-to-end Universe→World→Manuscript→Backup→Restore→Doctor chain. Zero `os.system()`, zero `shell=True`, zero `eval()`, zero bare `except:` anywhere in `scripts/`.Genuine test engineering with golden values. 282 unit tests across 51 Python modules + 9 shell regression suites, with `tests/test_domain_golden_values.py` validating astrophysics, climate, Lanchester, and Lorentz calculations against published scientific references with cited formulas and `assertAlmostEqual(... delta=...)` tolerances. The prose-linter ships a precision/recall corpus with positive AND negative labelled examples. Zero `TODO`/`FIXME`/`HACK`/`XXX` markers anywhere in the 25K-line codebase — a discipline almost unheard of in beta-stage software.Honest, documented governance. 37 Architecture Decision Records in `docs/ARCHITECTURE.md`, an explicit STRIDE-Lite threat model at `docs/THREAT_MODEL.md`, a Content-Security-Policy baseline enforced by CI test (`tests/test_threat_model.py:31-49`), `CONTRIBUTING.md` codifies invariants, `.github/copilot-instructions.md` enumerates non-negotiables, CI pins every Action by SHA, runs Gitleaks + Ruff + ShellCheck at `-S warning` + desktop-file-validate + a 4-distro matrix + a headless `xvfb-run` GTK smoke test. `SECURITY.md` discloses the sudo surface honestly. `PRIVACY.md` documents the zero-telemetry posture.Top 3 cross-cutting concerns:Architectural drift between aspiration and reality. The codebase presents a modular-monolith surface (50+ "engines", a registry, a UI controller, a CLI facade) but is structurally a script collection with decorative abstractions: the registry's `load_engine_module()` is never called for dispatch, the Python `cli.py` dispatcher duplicates the Bash dispatcher with different command coverage and is reachable only via `arcanum engines`, the `ui_controller.py` is dead code (only its test imports it), and adding a new engine requires coordinated edits to four files across two languages. The 3,873-line GTK god-window, 9 copies of `parse_yaml_frontmatter`, 9 copies of `resolve_world_dir`, and 18 nearly-identical `generate_*_html_report` functions are symptoms of this drift.Quality tooling below the project's own ambition. The Ruff configuration selects only 6 rule families out of ~30 Ruff ships; under `--select ALL`, 7,255 violations surface across 75 rule families, including 917 missing type annotations, 126 blind `except Exception` blocks, 48 silent `try/except/pass` patterns, 130 magic-value comparisons, and 55 over-branched functions. There is no `mypy`/`pyright`, no `coverage`/`pytest-cov`, no `hypothesis`, no `bandit`/`semgrep`. The `world_doctor.check_world` function runs at cyclomatic complexity 74 (3× the configured threshold of 25) and 186 statements. CI is green-but-shallow: it enforces the narrow configured ruleset but misses the broader backlog.Distribution and onboarding gaps that block 1.0 publication. The Flatpak manifest is non-functional: it omits `--talk-name=org.freedesktop.Flatpak` (so the sandboxed `arcanum write` cannot spawn Obsidian/novelWriter), and it bundles no `python3`/`typst`/`pandoc`/`jq` modules (so the Python dispatcher and export pipeline are unresolvable inside the sandbox). One Obsidian plugin (`longform`) has a SHA-256 mismatch between `dependencies.lock` and the vendored `main.js` — a real break of the project's own supply-chain integrity claim. The README promises a "starter cosmos with pre-configured lore and starter chapters" that does not ship in the repo. `gio set metadata::trusted true` does not actually trust launchers on modern XFCE — the literal first desktop double-click shows "Untrusted application launcher". There is no Scrivener/Word manuscript importer despite migration being a headline feature.Adoption recommendation: Adopt for the philosophy, the file-format sovereignty, the Typst publication pipeline, and the documented single-author Linux-Mint/Debian workflow. Do not adopt as the sole tool without (a) keeping a parallel plain-Markdown mirror via nightly rsync, (b) writing a custom Scrivener/Word migration script, and (c) treating the continuity engine as a safety net, not a substitute for human memory. Plan for 2–4 weekends of friction before the workflow feels native.---2. Cross-Cutting StrengthsBefore detailing the findings, it is important to record what the project gets right — both because the auditors independently surfaced the same strengths (convergent validation works in both directions) and because the improvement roadmap in §10 is calibrated to preserve these strengths while addressing the weaknesses.S-1 — Operational discipline uncommon for a beta. Every Bash file uses `set -euo pipefail`, NUL-delimited `find -print0 | while IFS= read -r -d ''` iteration, transactional `mktemp -d` staging with `trap cleanup EXIT INT TERM`, and explicit 4-value exit-code contracts (0 success / 1 operational failure / 2 env failure / 3 arg failure). The Typst binary download at `scripts/setup_arcanum.sh:312-327` is fail-closed SHA-256 verified, with explicit refusal on digest unavailability. The atomic-write primitive in `scripts/lib/fs_utils.py:12-65` is textbook POSIX crash-safety: `mkstemp` → `flush` → `fsync` → `os.replace` → parent-directory `fsync` → cleanup on `BaseException` (catches `KeyboardInterrupt` too). Zero `os.system()`, zero `shell=True`, zero `eval()`, zero bare `except:` anywhere in `scripts/` — verified by three independent auditors via `rg`.S-2 — Genuine test engineering with golden values. 282 unit tests across 51 Python modules + 9 shell regression suites + a 7-stage lifecycle harness (`scripts/verify.sh`) that sandboxes `$HOME`, unsets `DISPLAY`/`WAYLAND_DISPLAY`, and asserts end-to-end Universe→World→Manuscript→Backup→Restore→Doctor chains. `tests/test_domain_golden_values.py` validates astrophysics, climate, Lanchester, and Lorentz calculations against published scientific benchmarks with cited formulas and `assertAlmostEqual(... delta=...)` tolerances. The prose-linter ships a precision/recall corpus with positive AND negative labelled examples. Zero `TODO`/`FIXME`/`HACK`/`XXX` markers anywhere in the 25K-line codebase — a discipline almost unheard of in beta software.S-3 — Honest, documented governance. 37 Architecture Decision Records in `docs/ARCHITECTURE.md`, an explicit STRIDE-Lite threat model at `docs/THREAT_MODEL.md`, a CSP baseline enforced by CI test (`tests/test_threat_model.py:31-49`), `CONTRIBUTING.md` codifies invariants, `.github/copilot-instructions.md` enumerates non-negotiables, CI pins every Action by SHA, runs Gitleaks + Ruff + ShellCheck + desktop-file-validate + a 4-distro matrix + a headless `xvfb-run` GTK smoke test. `SECURITY.md` discloses the sudo surface honestly (`scripts/setup_arcanum.sh` and `scripts/uninstall_arcanum.sh` are the only `sudo` users). `PRIVACY.md` documents the zero-telemetry posture — verified by three independent auditors via `rg requests\.|urllib|urlopen|http\.client|socket\.` returning zero matches in `scripts/`.S-4 — File-format sovereignty. Plain Markdown (`.md`) source, standard OpenXML (`.docx`) sync via Pandoc, YAML manifests, local multi-tier Git version tracking, Typst (not InDesign) for print PDF, EPUB via Calibre. No proprietary formats, no cloud lock-in, no subscription. A novelist who abandons Ars Arcanum in 2030 can still read their manuscripts in 2075 with `cat` and `pandoc`. This is the project's reason for existing and it delivers.S-5 — Restore-engine hardening. `scripts/restore_world.sh:155-187` refuses to extract non-regular archive members: rejects absolute paths, `..` traversal, non-sample `.git/hooks/`, symlinks, hardlinks, FIFOs, device nodes. This is materially better than `tar -xzf` defaults and protects against malicious or corrupted backup archives on USB drives in drawers. The dual-target SHA-256 verified backup (`scripts/backup_world.sh:179-228`) replicates to two destinations and writes a `.sha256` sidecar — the intent is right, even though the implementation has a self-referential verification bug (see X-09).S-6 — Ubiquitous language discipline. 11 entity types (Universe, World, Manuscript, Book, Draft, Chapter, Character, Location, Faction, …) × 11 Obsidian `fileClasses` × 11 directory templates × 11 diagnostic code families all aligned. The Code Architecture auditor noted this as the single strongest architectural feature: the domain ontology is coherent and consistently named across Bash, Python, YAML, Markdown, and the GUI. ADR-022 ("Separated Lore & Manuscript Architecture") cleanly decouples prose from worldbuilding.S-7 — Cache invalidation done right. `scripts/lib/cache.py` uses mtime + size as the cache key with truncation flags and bounded reads. `tests/test_performance_cache.sh` enforces fast/slow cache parity (Test 4). Cache files are JSON-on-disk with atomic writes via the shared `fs_utils.atomic_write` primitive. The cache is per-project (`.arcanum_cache.json`) and per-draft (`.sync_state.json`), keeping cache scope tight — though the per-project `.gitignore` omission (X-10) means these files currently leak into Git history.S-8 — CI supply-chain hygiene. Every external GitHub Action is pinned by SHA-1 (not by tag), `permissions: contents: read` is declared at the workflow level, no `pull_request_target` triggers, Gitleaks runs on every push, and `dependabot.yml` is configured (though only for `github-actions` — see X-29). This is enterprise-grade CI hygiene for a single-maintainer beta.---6. Cross-Cutting Findings — Deduplicated TableThe table below lists all 47 deduplicated cross-cutting findings. Cross-Cutting Themes & Architectural PatternsThree architectural patterns emerged independently across multiple audits. They are not single findings — they are structural diagnoses that explain why so many of the findings exist.8.1 Theme A — "Script collection with decorative abstractions"The Code Architecture analyst's headline diagnosis is worth emphasising because it explains a disproportionate share of the cross-cutting findings. The codebase presents a modular-monolith surface (50+ engines, a registry, a UI controller, a CLI facade, a 797-line ARCHITECTURE.md with 37 ADRs) but is structurally a Unix-style script collection. The registry exists but is never called for dispatch. The UI controller is dead code. The Python CLI duplicates the Bash CLI with different coverage. Adding an engine requires editing four files. Nine copies of `parse_yaml_frontmatter` exist because there is no shared parsing layer. Forty-four copies of the `atomic_write` fallback boilerplate exist because each engine is designed to be runnable standalone, even though in practice they are only invoked via the dispatcher.This is not necessarily a bad architecture — Unix script collections have served for fifty years. But it is misrepresented by the surface area, and the misrepresentation causes real costs: a new contributor reads `ARCHITECTURE.md`, expects layering, finds none, and is confused. The fix is not to impose layering; it is to either (a) actually build the layered architecture the docs claim (Phase 4 of the roadmap in §10), or (b) rewrite `ARCHITECTURE.md` to honestly describe the script-collection architecture and delete the decorative abstractions (registry, ui_controller, parallel cli.py).8.2 Theme B — "Quality tooling below the project's own ambition"The Code Quality analyst's headline diagnosis is the second structural pattern. The project has aspirational engineering (281 tests, 37 ADRs, golden-value physics, SHA-pinned CI) but narrow enforcement (Ruff with 6 of ~30 rule families, no mypy, no coverage, no property tests, no SAST beyond Ruff). The result is a "green-CI trap": CI passes, the badge says "281/281 Passing", and the maintainer (justifiably) believes the codebase is in good shape. But `ruff check --select ALL` surfaces 7,255 violations, including 917 missing type annotations and 126 blind `except Exception` blocks that no tool currently flags. The `world_doctor.check_world` function runs at complexity 74 (3× the configured threshold) and CI does not catch it because the `select` list excludes the complexity-rule family that the `mccabe` config option configures.This is the single highest-leverage improvement the project can make: add `mypy`, `coverage`, `ruff --select ALL` (in a phased rollout), and `bandit` to CI. The existing tests are good — they will pass. The existing code is good — it will pass once the violations are fixed. The gap is purely in measurement, and measurement is cheap to add.8.3 Theme C — "Distribution and onboarding gaps that block 1.0 publication"The Linux Developer and End User auditors independently surfaced a cluster of issues that, taken together, mean the project is not yet ready for a 1.0 publication despite being ready in most other respects. The Flatpak manifest is non-functional (X-02). One Obsidian plugin has a SHA-256 mismatch in the supply-chain ledger (X-01). The README promises a "starter cosmos" that does not ship (X-23). The first desktop double-click on XFCE shows "Untrusted launcher" (X-14). The continuity engine's death regex misses poetic deaths (X-13). There is no Scrivener/Word importer (X-12). The WCAG contrast on the redline comparator fails AA (X-15). The default author name propagates to the PDF copyright page (X-24).None of these are individually fatal.
