Role 05 — Code Quality Analyst: Deep-Dive Audit of Scriptorium (Ars Arcanum)Repo: `/home/z/my-project/scripts/scriptorium`Audit date: 2026-09-21 (HEAD, post-v1.6.1 release)Scope: 101 Python files (~25,440 LoC in `scripts/lib/` + `scripts/*.py`) and 22 Bash scripts (~6,712 LoC), 51 Python test modules (~5,905 LoC), 9 shell regression suites (~1,572 LoC), `pyproject.toml`, `.github/workflows/ci.yml`, `dependencies.lock`, `DEPRECATION.md`, `CHANGELOG.md`, `CONTRIBUTING.md`.Tooling used: Ruff 0.16.8 (matching CI pin), `python3 -m unittest`, `bash -n`, ripgrep via the Grep tool.Auditor verdict: B (Strong Beta, with structural debt visible at the seams).---1. Executive SummaryScriptorium ("Ars Arcanum") presents an unusually disciplined beta: a 25K-line Python codebase that ships clean under its configured Ruff ruleset, passes 282/282 unittests (one intentional skip), is guarded by a 7-stage Bash verification harness, a 4-distro container matrix, Gitleaks secret scanning, and shellcheck at the `warning` threshold. The CI workflow pins every external action by SHA-1, declares `permissions: contents: read`, and ships a hardening narrative (`docs/THREAT_MODEL.md`, `SECURITY.md`, `DEPRECATION.md`) that most "production" projects half its age would envy.That said, the quality posture is asymmetric. The configured Ruff ruleset (`E, F, B, S, UP, SIM` + mccabe) is deliberately narrow — only 6 rule families out of the ~30 Ruff ships — which means the green CI is hiding a substantial backlog of unenforced issues. When the analyst re-ran Ruff with `--select ALL`, 7,255 violations surfaced across 75 distinct rules. The largest categories are documentation gaps (1,238 docstring violations), missing type annotations (917), 126 blind `except Exception` blocks, 48 silent `try/except/pass` patterns, 130 magic-value comparisons, 55 over-branched functions, and 48 over-long functions. The cyclomatic-complexity threshold of 25 is set permissively, yet the codebase still trips it 10 times — including one function (`world_doctor.check_world`) that runs at complexity 74 (3× the limit) and 186 statements. Major boilerplate duplication exists: the same 10-line `atomic_write` fallback and 5-line `sys.stdout.reconfigure` block are copy-pasted across 44 and 36 module heads respectively. No `mypy`/`pyright` configuration exists anywhere in the repo, so the codebase has zero static type-checking despite partial annotations. No `pytest`, no `hypothesis`, no property-based tests, no coverage measurement. The CHANGELOG advertises `[1.6.1] - 2026-09-21` while the source constant `VERSION = "1.6.0"` in both `scripts/arcanum:27` and `scripts/lib/cli.py:19` lags behind — a release-pipeline drift.Strengths: (1) strict CI supply-chain pinning; (2) golden-value tests against published scientific benchmarks (`tests/test_domain_golden_values.py`); (3) prose-linter precision/recall corpus (`tests/test_prose_linter_corpus.py`); (4) zero `TODO`/`FIXME`/`HACK`/`XXX` markers anywhere in the tree; (5) atomic-write infrastructure is genuinely crash-safe (`scripts/lib/fs_utils.py`); (6) a fail-closed `verify.sh` with mandatory-failure stages.Concerns: (1) Ruff config is too narrow and silence is being mistaken for cleanliness; (2) the 3,873-line `ui_gtk3.py` is a maintainability black hole (272 annotation gaps alone, 5 of the 10 longest methods, complexity 27+); (3) `world_doctor.check_world` at complexity 74 needs immediate decomposition; (4) no type checker, no coverage, no property tests; (5) `BLE001`/`S110` pattern of broad-swallow exception handlers suppresses diagnosability.Overall grade: B (good for a beta, materially below the production bar the project aspires to).---2.
