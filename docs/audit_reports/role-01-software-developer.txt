Engineering Practices Audit3.1 Code OrganizationStrength — module-per-domain pattern. `scripts/lib/` contains 46 single-purpose Python modules organized by domain (astrophysics, cartography, conlang, genealogy, magic_system, etc.), each exposing a `main(argv: list[str]) -> int` entry point. This makes engines independently testable, dynamically loadable (`scripts/lib/registry.py:485` `load_engine_module()` uses `importlib.import_module`), and CLI-discoverable via `arcanum engines`. The `EngineSpec` dataclass (`registry.py:21-33`) cleanly captures category, title, description, module name, CLI command, aliases, studio tab, and enabled flag — a textbook plugin registry.Weakness — god-class GTK file. `scripts/lib/ui_gtk3.py` is 3,873 lines containing a single class (`ArcanumApp(Gtk.Window)`, line 106) with only 4 module-level functions. This is the largest single concentration of complexity in the codebase. It mixes window lifecycle, 12 speculative-fiction dialog callbacks, six studio tabs, worker-thread management, command execution, DOCX sync, demo-world scaffolding, and Flatpak detection in one class. The test suite (`tests/test_ecosystem_ui.py:117`) resorts to reading the source file as text and grepping for method names rather than exercising the class — a clear sign the file has grown past testable unit boundaries. Severity: High. Recommendation: Split into `ui_gtk3/window.py`, `ui_gtk3/studios/{cosmos,drafting,speculative,publishing,safety,diagnostics}.py`, `ui_gtk3/dialogs.py`, `ui_gtk3/workers.py`, `ui_gtk3/cli_bridge.py`. Effort: L.Weakness — embedded Python in Bash. `scripts/arcanum_doctor.sh` is 466 lines but ~400 of those are a single Python heredoc (`python3 - << 'PYEOF' ... PYEOF`, lines 70-440+) implementing the entire diagnostic engine. `scripts/verify.sh` contains 5 separate Python heredocs (lines 91, 101, 114, 126, 318, 383, 412, 438). These heredocs cannot be linted by Ruff, cannot be type-checked, cannot be unit-tested in isolation, and cannot be reused by other callers. Severity: High. Recommendation: migrate `arcanum_doctor.sh` logic into `lib/diagnostics.py` (which already exists with 8 functions but is unused by the Bash dispatcher); replace `verify.sh` heredocs with `python3 -m arcanum.verify_stage N` calls. Effort: M per file.3.2 Error HandlingStrength — fail-closed discipline. `scripts/setup_arcanum.sh:312-327` is exemplary: Typst binary download fails closed on digest mismatch (`TYPST_OK=0`), explicitly refuses unverified binaries (`Refusing to install unverified binary: upstream SHA-256 digest unavailable`), and aggregates failures into `INSTALL_ERRORS=()` for honest end-of-run reporting. `scripts/lib/fs_utils.py:atomic_write` uses `os.fdopen`, `f.flush()`, `os.fsync(f.fileno())`, then `os.replace`, then `os.fsync` of the parent directory (lines 50-58), with cleanup on `BaseException` (catches `KeyboardInterrupt` too). This is textbook POSIX crash-safety.Weakness — broad `except Exception` swallowing. `scripts/lib/config.py:75` catches `Exception` broadly when loading JSON config (`logger.warning(...); return {}`), which is reasonable for a config file but masks `PermissionError`, `OSError`, and `json.JSONDecodeError` alike. `scripts/arcanum_app.py:27, 38, 84, 89` uses `except Exception as e: logger.debug(...)` for UI-launch fallbacks — defensible because the goal is best-effort probing, but the `logger.debug` level means failures are invisible to users unless they enable debug logging. Severity: Low. Recommendation: narrow to `(ImportError, RuntimeError, ValueError, gi.RepositoryError)` for UI probing; narrow config-load to `(OSError, json.JSONDecodeError)`.Weakness — `pyproject.toml` blanket-ignores 8 Ruff rules. Lines 8-16 ignore `S603` (subprocess untrusted-input check), `S607` (partial-path subprocess), `S311` (pseudo-random), `S110` (try-except-pass), `SIM105` (contextlib.suppress), `B905` (zip strict), `S608` (SQL injection). Several of these are reasonable for the project (`S311` — fiction RNG; `S608` — no SQL DB). But `S603` is the rule that flags `subprocess.run([bin, user_input])` patterns, and disabling it project-wide removes a critical guardrail. The 37 `subprocess.*` call sites in `scripts/lib/` and `scripts/arcanum_doctor.sh` are mostly safe (list-form argv, no `shell=True`), but `S603` would have flagged any future regression. Severity: Medium. Recommendation: re-enable `S603` and add `# noqa: S603` annotations only on the specific lines where subprocess input is genuinely trusted.3.3 LoggingStrength — `RotatingFileHandler` configured. `scripts/lib/diagnostics.py:57-80` sets up a `RotatingFileHandler` at `$XDG_STATE_HOME/ars-arcanum/arcanum.log` with 5 MB rotation, 3 backups, and structured `[timestamp] [LEVEL] [logger:module] message` format. Each engine module declares its own `logger = logging.getLogger("arcanum.<engine>")` (e.g., `arcanum.stylistics`, `arcanum.config`, `arcanum.package`).Weakness — no `logging.basicConfig` in CLI entry points. Several engine `main()` functions call `logger.warning(...)` without ever configuring handlers, so on a default `arcanum foo` invocation those warnings go nowhere. The `RotatingFileHandler` is set up only when `lib.diagnostics.setup_logging()` is explicitly called (which the Bash `arcanum doctor` path doesn't do because it bypasses `lib.diagnostics.py` entirely). Severity: Medium. Recommendation: call `setup_logging()` from `scripts/lib/cli.py:main()` and from `scripts/arcanum_app.py:main()` so all engines inherit the handler.3.4 Configuration ManagementStrength — XDG-correct with legacy fallback. `scripts/lib/config.py:42-62` resolves `$XDG_CONFIG_HOME/ars-arcanum/config.json` with fallback to `~/.config/ars-arcanum/config.json`, and gracefully reads from a legacy `~/.config/arcanum/config.json` if the primary path is empty. `save_config()` (line 80) writes with `0o600` permissions via `os.open(..., 0o600)` — proper for a file that may contain backup destination paths.Weakness — flat-manifest YAML parsing is brittle. `scripts/init_query.py:191-198` parses `manuscript.yaml` by splitting on the first `:` of each line:```pythonfor line in manifest_path.read_text(...).splitlines():    line = line.strip()    if ":" in line and not line.startswith("#"):        k, v = line.split(":", 1)        ...```This works for the project's flat manifests but silently mishandles multi-line YAML scalars, nested maps, lists with `- item` syntax, and quoted values containing `:`. `scripts/export_book.sh:161-166` does the same with `sed -n -E 's/^title:[[:space:]]*"?([^"#]+)"?[[:space:]]*(#.*)?$/\1/p'`. The codebase goes to lengths to avoid the `pyyaml` dependency (consistent with the "zero external deps" principle stated in `init_query.py:18`), but the result is two separate hand-rolled YAML parsers that will diverge on edge cases. Severity: Medium. Recommendation: either vendor a 200-line `yaml_lite.py` parser that handles the subset the project actually uses (flat keys + string/int/list values + comments), or admit `pyyaml` as a dependency (it's already in the standard library of most Linux distributions via `python3-yaml`).3.5 Environment HandlingStrength — `verify.sh` sandboxes `$HOME` and unsets GUI env. `scripts/verify.sh:36-46`:```bashTMP_VERIFY="$(mktemp -d)"ORIG_HOME="${HOME:-}"cleanup() { rm -rf "${TMP_VERIFY:-}"; ... }trap cleanup EXIT...export HOME="${TMP_VERIFY}/home"unset DISPLAY WAYLAND_DISPLAY 2>/dev/null || true```This is the correct pattern for running GUI-capable scripts in CI. The same pattern is repeated in `tests/test_audit_fixes.sh` and other shell test suites.Weakness — `$HOME` interpolation in shell `python3 -c` calls. `tests/test_audit_fixes.sh:383`:```bashpython3 -c "import xml.etree.ElementTree as ET; ET.parse('${HOME}/Manuscripts/XMLTest/nwProject.nwx'); print('  OK Test 21 passed: nwProject.nwx parses with special chars')"```In the test sandbox `$HOME` is a `mktemp -d` path, so it won't contain single quotes — but the pattern is exactly what `CONTRIBUTING.md:74-76` forbids. Severity: High (process-violation, not exploitation risk today). Recommendation: rewrite as `python3 -c 'import sys, xml.etree.ElementTree as ET; ET.parse(sys.argv[1]); print("  OK Test 21 passed")' "${HOME}/Manuscripts/XMLTest/nwProject.nwx"`. Same fix for the 30+ similar lines.---4. Every Bash script uses the same hand-rolled argument parser:```bashwhile [ $# -gt 0 ]; do    case "$1" in        -t|--title) [ $# -ge 2 ] || { echo "Error: --title requires a value." >&2; exit 2; }; VAR="$2"; shift 2 ;;        -h|--help) usage; exit 0 ;;        --) shift; while [ $# -gt 0 ]; do POSITIONAL+=("$1"); shift; done ;;        -*) echo "Error: unknown option: $1 (see --help)" >&2; exit 2 ;;        *) POSITIONAL+=("$1"); shift ;;    esacdone```This pattern is repeated in `init_manuscript.sh:51-72`, `export_book.sh:72-103`, `arcanum_doctor.sh:41-58`, etc. Every Python engine uses `argparse.ArgumentParser` with `--json` output flag, `--help`, and explicit `choices=[...]` for enum-like arguments (`arcanum_app.py:65-73`).Weakness — Bash arg parsing is hand-rolled, not getopt-based. The pattern works, but doesn't support `-tVALUE` (no space) or `--title=VALUE` (equals sign). Users expecting GNU getopt conventions will be surprised. Severity: Low. Recommendation: document the supported grammar in `CONTRIBUTING.md`, or migrate to `getopt --long` for consistency with GNU tools.7.2 Subcommand StructureStrength — discoverable command surface. `arcanum --help` (lines 29-104 of `scripts/arcanum`) lists every command grouped by studio (✍️ Core Authoring, 🪐 Universe/World Lore, 🔒 Data Protection, 🩺 System Health). Aliases are documented inline (`alias: diff, redline`). The `arcanum engines` command (via `lib/cli.py:93-108`) prints a tabular registry of all engines with category, name, command, and title.Weakness — command aliases are inconsistent. `arcanum` (Bash) accepts `export|publish|build|compile` as aliases for `export_book.sh` (`scripts/arcanum:527`), but `lib/cli.py` doesn't have an `export` route at all. `arcanum word|writer|word-processor` (Bash, line 515) routes to `docx_sync.py open`, but there's no Python equivalent. Severity: Medium (finding 4.3).Strength — "did you mean?" suggestion. `scripts/arcanum:696-721` uses `difflib.get_close_matches(cmd, known_commands, n=1, cutoff=0.55)` via an inline Python heredoc with proper argv passing (`python3 - "${COMMAND}" << 'SUGG_EOF'`) — this is the correct pattern and a deliberate contrast to the `python3 -c` violations elsewhere. The 55% cutoff is reasonable.7.3 Exit CodesStrength — 4-value exit-code contract documented and enforced. `CONTRIBUTING.md:24-37` and `.github/copilot-instructions.md:20-30` both document:`0` success`1` runtime/diagnostic failure`2` usage/environment error`3` nothing to act on (clean tree, no GUI fallback, user abort)Every script I sampled follows this. `init_manuscript.sh:109` exits 3 when no name is provided in headless mode. `export_book.sh:119` exits 3 when no manuscript is selected. `setup_arcanum.sh:48` exits 2 on unknown option. `verify.sh:660-672` distinguishes `ALL-CHECKS-PASS` (0) from `PASS (with N skips)` (0 unless `--require-tools`) from `FAIL` (1). This is exemplary.Weakness — Python engines don't uniformly honor the contract. `lib/cli.py:84` does `return mod.main(argv) or 0`, which means an engine returning `None` (e.g., one that forgot to `return 0` at the end of `main()`) becomes exit 0 — masking bugs. `lib/config.py:264, 266, 270, 273` calls `sys.exit(0)` and `sys.exit(1)` directly inside `main()` rather than returning the exit code, which prevents the caller from doing any post-processing. Severity: Medium. Recommendation: establish a convention that all `main()` functions return `int` and never call `sys.exit()` directly except in `if __name__ == "__main__": sys.exit(main())`.7.4 Output FormatsStrength — consistent `--json` flag. Every Python engine I sampled (`init_query.py:171`, `package_distribution.py:179`, `config.py`, `astrophysics.py` per `verify.sh:429-432`) supports `--json` for machine-readable output. The JSON shapes are documented in `verify.sh`'s assertion code (e.g., `assert d['peak_velocity_c_fraction'] > 0.9`).Weakness — no `--yaml` output. The project stores all manifests in YAML but never emits YAML from any engine. A user wanting to pipe `arcanum economy <world> --json | jq` into a YAML-consuming tool must convert manually. Severity: Info.7.5 Help TextStrength — `arcanum --help` is comprehensive. 76 lines of grouped, emoji-decorated command listings with inline aliases and feature IDs (`PUB-101`, `WOR-101`, `INT-101`). This is friendly for new users.Weakness — per-command help is inconsistent. `arcanum export --help` runs `export_book.sh` with no args, which prints `usage()` and exits 2 (because `TARGET_DIR` is empty). But `arcanum calc --help` runs `astrophysics.py` with `--help`, which prints argparse help and exits 0. The exit code for "user asked for help" should always be 0, but `export_book.sh`'s no-args path exits 2 (via the "no manuscript selected" check at line 117-120). Severity: Low. Recommendation: add an explicit `--help` short-circuit at the top of every Bash script's arg parser, before the `TARGET_DIR` check.---8.
