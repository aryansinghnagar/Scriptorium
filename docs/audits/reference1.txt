Detailed Findings — Functionality (Correctness)F-01 [P0] `control_center.sh` crashes on undefined `WORLDS_BASE`Location: `scripts/control_center.sh:33-34````bash  mkdir -p "${UNIVERSES_BASE}"  mkdir -p "${WORLDS_BASE}"  ```Contract: `scripts/lib/worlds.sh:38-40` exports `UNIVERSES_BASE`, `MANUSCRIPTS_BASE`, `LEGACY_WORLDS_BASE`. There is no `WORLDS_BASE`.Effect: Under `set -u` (line 7), this is `WORLDS_BASE: unbound variable` → immediate exit before `discover_worlds`. The Zenity fallback path — the advertised safety net when GTK is absent — never runs.Repro: `bash scripts/control_center.sh` on a headless / no-GTK machine with `DISPLAY`/`WAYLAND_DISPLAY` unset, or directly invoke after sourcing lib; observe unbound-variable abort.Fix direction: `mkdir -p "${MANUSCRIPTS_BASE}"` (or legacy base if that was intent) — verify intent; add a regression test invoking the fallback with GTK absent.F-02 [P0] GTK3 GUI dispatches to `scripts/scripts/...`Location: `scripts/lib/ui_gtk3.py:40-41````python  SCRIPT_DIR = Path(__file__).resolve().parent   # .../scripts/lib  PROJECT_ROOT = SCRIPT_DIR.parent                # .../scripts  (misnamed)  ```Call sites (verified by grep): `:1080, :1111, :1147, :1189, :1202, :1211, :1243, :1265, :1365, :1382, :1407, :1414, :1426, :1442-1444` all do `PROJECT_ROOT / "scripts" / "<name>.sh"` → `.../scripts/scripts/...`.Contrast: `scripts/lib/ui_adw.py:30` uses `.parent.parent`, so its `SCRIPT_DIR` is actually `scripts/`. Inconsistent convention, same misnamed variable. One of the two is wrong by construction.Effect: From the 5-tab Control Center (the daily driver for the target beginner user), every 1-click action that shells out — init universe/world/manuscript, snapshot, backup, restore, export, concordance, doctor, verify, demo seeding — fails with file-not-found.Fix direction: Standardize on `PROJECT_ROOT = Path(__file__).resolve().parent.parent.parent` for files under `scripts/lib/` (repo root), `SCRIPT_DIR = PROJECT_ROOT / "scripts"`, and route all subprocesses through one helper with an existence assertion + test.F-03 [P0] Installed `scriptorium` dispatcher breaks under symlinkLocation: `scripts/scriptorium:9-13````bash  SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"  PROJECT_ROOT="$SCRIPT_DIR"  if [ ! -f "${PROJECT_ROOT}/scripts/verify.sh" ]; then      PROJECT_ROOT="$(dirname "$SCRIPT_DIR")"  fi  ```Effect: Source-tree invocation works. Packaged invocation via symlink (`debian/rules` → `/usr/bin/scriptorium`, `org.scriptorium.Scriptorium.yaml:32` → `/app/bin/scriptorium`) leaves `BASH_SOURCE[0]` as the symlink path without `readlink -f`. `SCRIPT_DIR=/usr/bin`, fallback `PROJECT_ROOT=/usr`, then `exec bash /usr/scripts/...` fails for every subcommand.Fix direction: Resolve with `readlink -f "${BASH_SOURCE[0]}"` (with macOS-incompatible fallback if needed — Linux-only project, so `readlink -f` is fine), then probe both layouts explicitly. Add a packaged-layout test (symlink farm + `PROJECT_ROOT` assertion).F-04 [P0] Installed `.desktop` launchers contain literal `__PROJECT_ROOT__`Location: `launchers/scriptorium-control-center.desktop:7` (and siblings): `Exec=bash "__PROJECT_ROOT__/scripts/control_center.sh"`.Evidence: Only `scripts/setup_scriptorium.sh:357` performs the substitution. `org.scriptorium.Scriptorium.yaml:31` (`cp launchers/*.desktop`) and `debian/rules` copy verbatim. `ci.yml:78` runs `desktop-file-validate` on the unsubstituted source, so it validates syntax but never the installed artifact. `TryExec=bash` always succeeds and masks the failure in menus.Effect: On `.deb` / Flatpak installs, clicking any Scriptorium launcher runs `bash` with a non-existent literal path. The flagship "zero terminal required" promise fails at the desktop entry.Fix direction: Substitute at packaging time in both `debian/rules` and the Flatpak `build-commands` (or switch to absolute installed paths `/app/share/...`, `/usr/share/...`), and add a post-substitution `desktop-file-validate` + `grep -r __PROJECT_ROOT__` gate.F-05 [P0/P1] Restore engine: staging leak, empty-name risk, unsanitized `--dest`, fail-open checksumAll in `scripts/restore_world.sh` (read in full, 216 lines):Inverted cleanup (functional leak): `SUCCESS=0` initially; `cleanup()` removes `$STAGING_DIR` only when `SUCCESS==0`; success path sets `SUCCESS=1` at `:205` after `mv`. Net: failures clean up, successes leak an empty `$STAGING_DIR` in `/tmp` every restore. Over months of author use this accumulates.Empty-name `mv` (safety): `:163` sanitizes via `tr -cd 'A-Za-z0-9_-'`. Input `"!!!"` → `""` → `TARGET_FINAL_DIR="${DEST_PARENT}/"` → `mv "$EXTRACTED_DIR" "$DEST_PARENT/"` moves the world into the parent without its directory wrapper. No empty-check.Unsanitized `--dest` (safety): `:166-167` accepts any `--dest` verbatim, unlike `scripts/backup_world.sh:108-114` which allow-lists `$HOME` / `/tmp` / `/var/tmp`. `restore --dest /etc/...` or `--dest /` is an arbitrary-write primitive (constrained by user perms, but still outside the data model).Fail-open integrity (security-functionality): `:109-111` — missing `.sha256` sidecar prints "skipping hash check" and continues. Anyone who can replace the archive can delete the sidecar to bypass verification. Should warn loudly and require `--force` or fail.Positive (keep): `:137-150` traversal / absolute / root-escape / non-sample `.git/hooks` refusal + `--no-same-owner` is correct and well-commented. Do not regress.F-06 [P1] Backup includes `.git`, is non-reproducible, has no size guardLocation: `scripts/backup_world.sh:138-149`. Excludes `Backups/Exports/04-Publishing/workspace.json/cache/*.bak/*.tmp/*.log` but not `.git/`.Effects: (a) Every backup duplicates full Git history → large, slow archives; restores re-import history the user may not expect. (b) No `--sort-name --mtime --owner/--group` → byte-non-reproducible archives; SHA proves integrity of that byte stream, not equivalence across runs. (c) No size / disk-space pre-check before `tar -czf`.Also: `:138` `tar` of `.git/` can leak secrets if the author ever committed tokens (common beginner mistake). Either exclude `.git` or document that inclusion is intentional (history-preserving disaster recovery) and add a secret-scan warning.F-07 [P1] `--fast` doctor flag warms a cache it then discardsLocation: `scripts/world_doctor.sh:147-155` calls `lib.cache.scan_project()` then proceeds to re-walk with `os.walk` regardless.Effect: The flag is misleading; users with large vaults see zero speedup and conclude the tool is slow. Either thread the cache through the checks or remove the flag until it is real.Related scaling note: `scripts/scriptorium_doctor.sh` wraps `world_doctor` in a 15s timeout; vaults >10k notes will hit it and record `{"error":...}` silently. Surface timeouts as warnings with remediation ("use --fast / split vault"), not silent JSON.F-08 [P1] Three word-count definitions diverge`scripts/lib/cache.py:107` → `len(re.findall(r"\b\w+\b", ...))``scripts/wordcount_report.sh:116` (per prior audit; verify locally) → `\S+`-based`scripts/lib/ui_gtk3.py:838-876` → `split()` on full re-read per selection change, no mtime cache (self-admitted in `docs/codebase/CONCERNS.md`)Effect: Same manuscript shows three totals depending on where the author looks (dashboard vs report vs cache). For a writing tool, word count is the scoreboard — divergence erodes trust.Fix direction: Canonicalize one definition (document hyphen / em-dash / code-block policy), route all three through `cache.py`, and cache the analytics path.F-09 [P1] Toolchain pin drift + dependency classificationPins: `dependencies.lock:12` + `scripts/setup_scriptorium.sh:254` pin Typst `0.13.0`; `ci.yml:45` floats `0.13`; docs reference `0.15.1`. Patch-float CI + doc skew = non-deterministic template breaks (Typst is fast-moving; header/footer query semantics change).Debian deps: `debian/control:14-28` puts `pandoc`, `jq`, `curl`, `xz-utils`, `zenity` in `Recommends`, but `scripts/export_book.sh:373,442` hard-requires Pandoc/JQ paths and 11 scripts branch on `has_gui`→zenity. Gate log creation behind `DRY_RUN==0` or log to stdout-only in dry-run. Also `curl -L -f -sS` at `:283` has no `--retry/--max-time` (acknowledged in `CONCERNS.md`; still a hang risk on flaky hotel Wi-Fi — the author's likely writing environment).F-10 [P1] GUI responsiveness and subprocess hygiene`scripts/lib/ui_gtk3.py:1273,1384,1421` — `for line in proc.stdout: GLib.idle_add(...)` floods the main loop on large `verify.sh` output; use batched appends or a bounded queue.`:1303,1313,1323,1509` — `Popen(["xdg-open",...])` never reaped, no return-code check; zombies + silent failures on missing handler.`:1404,1409` — `subprocess.run` without `timeout`; a hung Typst/Pandoc compile freezes the worker thread indefinitely.Why P1 not P0: Worker threads (`daemon=True`) keep the UI nominally alive, but large-manuscript authors will see jank / hangs.F-11 [P1] Continuity engine: non-determinism + swallowed errors`scripts/lib/continuity.py:239-257` picks `universes[0]` / `mss[0]` when multiples exist — non-deterministic across filesystems.
